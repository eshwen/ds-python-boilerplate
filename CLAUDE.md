# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A boilerplate/template for Python data science projects. The actual code (`src/my_project/hello_world.py`) is a placeholder; the value is in the tooling configuration (`pyproject.toml`, `.pre-commit-config.yaml`, `mkdocs.yml`, `.github/workflows/`) and the MkDocs site under `docs/` that explains it. Changes are often dependency bumps (Dependabot) or tooling updates rather than feature work.

## Commands

Managed with `uv` (version pinned via `[tool.uv] required-version`). Python 3.11–3.14 is supported; 3.11 is the baseline (`requires-python`, ruff `target-version`, pyrefly `python-version`).

```shell
uv sync                  # main deps + dev group (lint, type, test, jupyter)
uv sync --all-groups     # also installs the docs group (needed for mkdocs)

uv run pytest                                                   # all tests, with coverage (fails under 90%)
uv run pytest -k test_hello_world --no-cov                      # single test
# --no-cov: otherwise a partial run trips the 90% coverage gate.
# Use -k: selecting by node ID (file::test) still collected the whole file here.

uv run ruff check --fix src/ tests/
uv run ruff format src/ tests/
uv run pyrefly check     # type check (scope comes from [tool.pyrefly] config)
uv run pre-commit run -a # everything pre-commit runs, incl. uv-lock/uv-sync

uv run mkdocs build --strict   # CI runs this; warnings fail the build
uv run mkdocs serve            # local preview
```

A Claude Code `PreToolUse` hook (`.claude/hooks/check-before-commit.sh`) blocks any `git commit` until `pre-commit run` (staged files) and `pytest` pass.

## Conventions enforced by tooling

- **Docstrings**: Google style, checked by ruff's `D` rules (required on public functions/modules in `src/`; relaxed in `tests/` and `__init__.py`). Docstrings feed the generated API reference, so cross-references like `[pandas.DataFrame][]` resolve via the mkdocstrings inventories in `mkdocs.yml` — keep them valid or `mkdocs build --strict` fails.
- **Typing**: pyrefly runs in `strict` preset on `src/` only (tests excluded); unannotated return types are errors. Missing stubs go in the `type` dependency group.
- **Tests**: files must be named `test_*.py` (pre-commit `name-tests-test --pytest-test-first`). `asyncio_mode = "auto"`, so async tests need no decorator. Coverage uses branch coverage with `fail_under = 90`.
- Line length is 120. Ruff also enforces pandas-vet (`PD`), pathlib (`PTH`), pylint (`PL`) and pyupgrade (`UP`) rules.
- pre-commit also runs `auto-walrus`, which rewrites assignments into walrus expressions.

## Architecture / cross-file coupling

- **Package name `my_project`** is referenced in several places that must change together if renamed: `pyproject.toml` (`[project].name`, `[tool.coverage.run].source`), `mkdocs.yml` (`api-autonav` `modules: ['src/my_project']`), `.github/workflows/test.yml` (`pkg-name`), and test imports.
- **API docs** are auto-generated by `mkdocs-api-autonav` + `mkdocstrings` from `src/my_project` (a "Code Reference" nav section) — no hand-written API pages.
- **Versioned docs** are published with `mike` to `gh-pages` only when a GitHub release is published (`api-docs.yml`), as `<major>.<minor>` aliased to `latest`.
- **CI** delegates most steps to reusable workflows/actions in `eshwen/adrenaline` (`python-quality-check-uv.yml` for ruff + pyrefly, `uv/test-python` for pytest). Tests run on a 3.11–3.14 matrix and also build docs strictly.
- **Version sync**: the ruff `rev` in `.pre-commit-config.yaml` should match the ruff version in `uv.lock`. The `pyrefly-pre-commit` rev is the hook version, not the pyrefly version.
- Release notes are drafted automatically by release-drafter from PR labels (auto-applied via `.github/release-drafter-config.yml`).
